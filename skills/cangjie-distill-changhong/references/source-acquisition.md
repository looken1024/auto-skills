# 找不到全文时的取源顺序（实测）

## 1. 先扫本地

```bash
find ~ -maxdepth 4 \( -iname "*书名*" -o -iname "*.epub" -o -iname "*.mobi" -o -iname "*.azw3" \) 2>/dev/null
```

没有就明说“本地没有”，不要默认用户手上有文件。

## 2. 合法公开渠道（按可用性排序）

| 渠道 | 能拿到什么 | 注意 |
|---|---|---|
| 微信读书搜索接口 `https://weread.qq.com/web/search/global?keyword=<书名>` | 书籍元数据 + 出版方简介（JSON，含 bookId / 作者 / 译者 / intro） | 正文要登录，接口拿不到全文 |
| 豆瓣 `https://book.douban.com/subject/<id>/reviews` | 20 篇左右公开书评，常含结构分析、案件梳理、人物剖析 | 书评观点是二手解读，不能当原文引用 |
| 豆瓣书籍主页 | 内容简介、作者简介、出版信息 | 目录常被反爬成“展开” |
| 维基百科 / Google Books | 词条概要、样章 | 本机直连不可达时可试系统代理；仍不通就换渠道 |
| 百度百科 / 知乎 | 词条与讨论 | curl 常返 403 安全验证，不要硬刷 |

**不抓盗版全文**。网上流传的 TXT/EPUB 基本都是盗版站，抓取和转存都不做；用户要全文时让他提供正版文件（EPUB/PDF/TXT）。

## 3. 只能拿到二手资料时

用户明确要求继续，才做「公开资料级蒸馏」，并在产出里写死这几条：

- `BOOK_OVERVIEW.md` 顶部单列一节「来源与局限」：写明未使用全文、用了哪些公开资料、细节可能不精确。
- R 段不引用原文（零引用），改写为“作品结构事实”（不写对白、不写句子）。
- 阶段 1 不做“5 路原文提取”，只做两路：结构事实 + 通行解读；把有争议的解读（如人物动机之争）排除在规则之外。
- 技能 B 段注明“细节需正版文本核对”，不声称是全文级蒸馏。

## 4. 本机输出路径

skill 里写的 `KB_ROOT=H:/长红的工作间/蒸馏知识库/` 是 Windows 路径，本机不存在。Linux 上落到：

```
~/.hermes/distill/<作品-slug>/
├── BOOK_OVERVIEW.md
├── INDEX.md
├── test-prompts.json
└── <skill-slug>/SKILL.md
```

自用技能再复制一份到 `~/.hermes/skills/<skill-slug>/SKILL.md` 才会被加载。
