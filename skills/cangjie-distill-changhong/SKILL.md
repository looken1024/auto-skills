# 🎨 仓颉蒸馏长红版 — 知识蒸馏流水线（内置内容预检）

> **定制者**：长红（高长红）
> **基础**：仓颉造技能（jifengmax-cangjie-creator）阶段 0-4 蒸馏法
> **增强**：阶段 5 发布内置 **主题分类 + 内容适配 + 渐进发布 + 频率退避**
> **最后更新**：2026-08-25（v1.5.0）

---

## 🎯 使命

把任意**作品**（书/文章/视频/课程/文档）中的方法论、框架、原则、清单、模式，蒸馏成一组**原子化、可被 AI Agent 在真实场景下调用的 skills**，并**稳妥地**发布到 **SkillHub（默认主目标）/ 本地用户级目录（可扩展至任意平台）**。

### 边界

| 做 ✅ | 不做 ❌ |
|------|---------|
| 方法论 / 决策框架 / 清单 / 原则 / 概念体系蒸馏 | 普通书摘 / 读后感 / 内容概括 |
| 多作品交叉蒸馏（多源融合） | 单篇内容的简单翻译 |
| 发布到 SkillHub（默认）/ 本地（**带预检 + 渐进**） | 不做预检直接发布、批量上线、反复重发 |
| 中文书蒸馏（**R 段原文引用需内容适配**） | 引用原文未经适配直接写入 |

## 📥 输入要求

**每次开工前确认以下四项：**

1. **作品来源** — 文件路径（PDF/EPUB/TXT/MD）或链接/URL
   - ⚠️ **绝对不能**凭空记忆提取——没文本就停下来问
   - **取源顺序**：先查本地（`find ~ -iname "*书名*"` 和常见电子书后缀）；本地没有再走合法公开渠道（微信读书/豆瓣书籍页、公开书评、作者访谈）；**不抓盗版全文**。各渠道的实测可用性、二手资料级蒸馏的写法、本机输出路径见 `references/source-acquisition.md`。
   - 合法渠道只能拿到二手资料、而用户明确要求继续时，可产出「公开资料级蒸馏」：BOOK_OVERVIEW 顶部写清 source grade 与“未使用全文”，技能 B 段注明细节需正版文本核对；**不得把书评观点伪装成原文引用**。
   - 二手资料级不跑阶段 1 的“5 路并行原文提取”，改为“结构事实 + 通行解读”两路，避免把推测写成书里的内容。
2. **作品名称** — 书名/文章名 + 作者 + 年份
3. **蒸馏目标** — 🅰️ 单一技能 / 🅱️ 多技能包 / 🅲️ 补完现有 skill
4. **是否发布到技能平台** — 若发布，必须走阶段 5 预检（中文书默认走）

## 🔄 执行流程（阶段 0-4 同原仓颉，略述；阶段 5 详述）

### 阶段 0-4（同原仓颉，关键差异在阶段 2 的 R 段适配）

- **阶段 0** 整书理解 → `BOOK_OVERVIEW.md`，汇报骨架等确认
- **阶段 1** 5 路并行提取 → `candidates/`
- **阶段 1.5** 三重验证 → `rejected/`
- **阶段 2** RIA++ 构造。**长红版关键点**：R 段若摘抄原作者原文，**先做内容适配**再写入。识别方式见 5.0 节分类表（不具体列举示例名称，只按类别代号处理）。
- **阶段 2.5（长红版新增 · Knowledge 轨）** 每个 skill 定稿后，同步生成 1 张 L1 知识卡片（格式见「知识库落盘规范」），写入 `KB_ROOT`（默认 `H:/长红的工作间/蒸馏知识库/`）。卡片与 skill 同源、共享同一原则，但面向「检索 / 比对 / 进化」，不负责可执行；同时挂到对应 L2 主题文件，并在 L3 综合区标记「待跨书比对」项。
- **阶段 3** 关联 + `INDEX.md`，并校验所有 `./slug` 跨链指向有效（避免中途换 slug 产生孤儿链接）
- **阶段 4** 压力测试 → `test-prompts.json`

### 阶段 5 — ☁️ 发布到技能平台（长红版增强 · 强制预检）

#### 5.0 内容预检（蒸馏阶段就该做，不要发布时才救火）

**A. 主题分类（最关键，先于细节）**

| 等级 | 主题类型 | 处理 |
|---|---|---|
| 🔴 注意 | 金融实操类、含具体操作信号/仓位/择时买卖/投资建议等 | 改写为"纯方法论/教育框架"（去掉一切具体市场操作）；或征询用户是否值得发；**建议不发布** |
| 🟡 一般 | 一般商业/管理/营销/产品类，可能涉及操作流程 | 替换为通用方法论表述，弱化具体人名/品牌/事件 |
| 🟢 安全 | 纯心理学/行为科学/决策思维/自我管理/学习方法/通用方法论 | 正常发布 |

> 若主题本身需要关注，**功能定位**（如"信号识别 + 行动判断"）即便换掉词面表达，仍可能被语义识别为相关品类。软化措辞 + 免责声明救不了**主题本身需注意**。

**B. 细节层（中文书特别要扫 R 段原文引用）**

| 类别 | 描述 | 处理 |
|---|---|---|
| 🔴 H1 | 历史叙事、历史类比 | 保留骨架，换载体名 |
| 🔴 H2 | 市场违规/合谋类写实描写 | 中性化改写 |
| 🔴 H3 | 真实公众人物姓名 | 改用学术概念或通用称谓 |
| 🟡 M1 | 重大历史事件/政策时点 | 软化或去除 |
| 🟢 L1 | 通用市场参数（涨跌幅区间等） | 暂安全，仍是变量 |

> **关键原则**：本 skill 自身不列举任何具体词汇（避免自身触线）。实操时按上表分类代号（H1/H2/H3/M1/L1）执行内容适配，参照 5.0.C 的"具体操作 SOP"。

**C. 具体操作 SOP（不展示反例，只描述流程）**

1. 对每个候选 skill，先在主题分类（A）打等级：🔴/🟡/🟢
2. 🔴 主题：直接走"主题改写"路径（功能定位转"方法论/教育"）或征询用户
3. 🟡 主题：对 R 段做细节层（B）逐类扫，按类别代号 H1/H2/H3/M1 做内容适配
4. 🟢 主题：正常进入 5.1 渐进发布
5. **所有适配痕迹以注释形式记入 PUBLISH_REPORT.md**，便于审计

#### 5.1 渐进发布（强制流程）

1. **先发 1 个最安全的**（纯原则/自检类，如总纲/自检类）→ **等平台反馈**（通过 or 反馈说明）。
2. 通过 → 确认边界，逐个发布其余；被拒 → **获取平台反馈再修**，不凭记忆硬改。
3. 探针被拒且属"主题/语义"层 → 软化无效，必须**改写主题定位**或**不发布该主题**。

#### 5.2 被拒后处理

- 获取 **UI/平台反馈原文** → 对症修。
- 反馈缺失 → 视为"无证据"，按主题分类（A）重新评估，**不凭记忆硬改**。
- 不要反复批量重发——每轮重发都是真实试错成本。

#### 5.3 频率退避 + slug 前置

- 批量发布遇频率限制 → 间隔 **12–25s** 重试即可，无需换 token。
- 已下线 slug 被平台 DB **永久占用**，CLI 无覆盖机制 → 中途换 slug 会产生**孤儿链接**。
- **发布前定好 slug 命名规范**，避免中途换名；跨链 `./旧slug` 全部改为 `./新slug`。

#### 5.4 发布目标与接口（明确地址 + 预留扩展）

蒸馏产物的发布以「**发布适配器（Publisher）**」抽象。当前内置 **SkillHub（默认主目标）** 与 **本地用户级目录** 两个，并预留任意第三方平台接口，使用者可按规则扩展。

| 接口 ID | 目标 | 地址 / 机制 | 状态 |
|---|---|---|---|
| `PUB-SKILLHUB` | **SkillHub（默认主目标）** | 本地 CLI `~/.skillhub/skills_store_cli.py`，发布到登录账号的 SkillHub（非公开 Marketplace） | ✅ 内置 |
| `PUB-LOCAL` | 本地用户级技能目录 | 复制到 `~/.workbuddy/skills/<slug>/` | ✅ 内置 |
| `PUB-<自定义>` | 其他平台 / Marketplace / 私有部署 | 实现 `publish(skill_dir) -> receipt` 适配函数 | 🔲 预留 |

##### 5.4.1 PUB-SKILLHUB —— 明确发布地址

- **CLI 路径**：`C:/Users/34963/.skillhub/skills_store_cli.py`（运行时优先 `which skills_store_cli.py`，fallback 到 `~/.skillhub/`）。
- **鉴权**：token 由用户持有，通过 `--token <skh_...>` 传入；也可写入 `~/.skillhub/` 配置由 CLI 自动读取。**不硬编码进 skill**。
- **预检（不发起请求）**：
  ```bash
  python skills_store_cli.py publish "<skill目录绝对路径>" --dry-run --json
  ```
- **正式发布**：
  ```bash
  python skills_store_cli.py publish "<skill目录绝对路径>" --token "<skh_...>" --changelog "蒸馏来源+版本说明" --json
  ```
- **回执**：`{"ok": true, "skillId": "17xxxx", "reviewStatus": "pending"}` —— `pending` 表示进入平台内容审核队列，**非即时公开**。
- **必填 frontmatter**（缺任一报错）：`name` / `description` / `slug` / `version` / `displayName`，首行必须为 `---`。
- **频率**：批量按 **25s/个** 节奏；遇 `429` 等待 25s 重试，无需换 token。
- **详细安检、拒绝处理、路径陷阱**见 `skillhub-publish-safety` skill（强制先走 5.0 预检 + 5.1 探针式）。

##### 5.4.2 PUB-LOCAL —— 本地安装（专家中心可用）

- 复制 `SKILL.md` 到 `~/.workbuddy/skills/<slug>/SKILL.md`。
- **必须含**：`agent_created: true` + `version` + `displayName` + `slug` + `triggers`，否则左侧「专家」中心不收录。
- 效果：专家中心直接可见可用，**无需信任/激活**（区别于 MCP 连接器）。
- 适用：仅本机自用、不上架公开平台时使用。

##### 5.4.3 预留扩展（使用者如何接入新平台）

1. 实现一个 `Publisher`：输入 **skill 目录绝对路径**，输出平台回执（skillId / url / status）。
2. 在上方「发布目标表」登记接口 ID 与机制说明。
3. **复用阶段 5.0 预检 + 5.1 渐进发布**——不因平台变化跳过预检。
4. 必要时在 `skillhub-publish-safety` 增补该平台的安检细则。

> 无论发布到哪个接口，阶段 5.0 主题预检与 5.1 探针式发布**强制保留**，这是蒸馏成果稳妥上线的底线。

## 📚 知识库落盘规范（Knowledge 轨 · 长红版新增）

**目的**：蒸馏时一手出 skill（可执行），一手出知识卡片（可检索/可进化），二者同源可追溯。详见 `H:/长红的工作间/蒸馏知识库/README.md`。

**KB_ROOT 常量**：`H:/长红的工作间/蒸馏知识库/`（C 盘外，H 盘长红目录）。

**书 slug 规则**：`<书名简称>-<作者>`，如 `炒股的智慧-陈江挺`。

**落盘动作（每个 skill 完成时）**：
1. 用 `_templates/CARD_TEMPLATE.md` 生成 `KB_ROOT/cards/<书-slug>/card-<同源 skill slug>.md`，填 YAML 元数据（tags / confidence / verifiable / verified / related_skills）。
2. 在 `KB_ROOT/topics/<对应主题>.md` 的「卡片清单」追加一行链接（主题按实战维度：心态/风控/选股/仓位/入场/出场/量价）。
3. 若该原则与已有卡片构成共识/冲突，在 `KB_ROOT/synthesis/` 新建或更新一条综合；否则在 `_index.md` 标记「待跨书比对」。
4. `verifiable=true` 的卡片，把假设同步进 `KB_ROOT/bridge/待验证假设.md`，供 backtest-audit-kit / 量化作弊器验证。

**约束**：
- 卡片引用原文 ≤150 字/段，且须已做内容适配（与 stage 2 同源检查）。
- `verifiable=true` 必须填「可证伪声明」，否则只是格言。
- 不凭空记忆写卡片——内容须源自当次蒸馏的真实文本/扫描读图产物。

## 📊 质量红线（长红版）

1. ❌ 每个 skill 必须通过**全部**三重验证（V1/V2/V3）
2. ❌ 每个 skill 必须有完整 **R/I/A1/A2/E/B** 六段
3. ❌ 原文引用 ≤150 字/段
4. ❌ 必须有 `test-prompts.json`，含诱饵测试
5. ❌ `description` 必须明确 trigger 条件
6. ❌ **绝对不能**凭空记忆提取——没文本就停下来问
7. 🛡️ **R 段原文引用经细节层预检**（中文书必查）
