# history-social-writing —— 历史×社会问题公众号写作（含参考文献铁律修订与格式沉淀）

面向公众号「棱镜折射」及其他历史社会类内容。核心公式：

**一个历史事件 → 一个当下社会问题 → 引发共鸣与思考 → 驱动转发/关注**

## 定位与读者

- 公众号：棱镜折射（未认证订阅号、主体个人）
- 目标：涨粉、阅读量、转发、关注
- 读者：泛大众，非历史专业，但喜欢「长见识 + 有共鸣 + 看得懂」
- 文风：有观点、口语化、反 AI 味，反对学术腔与标题党空转

## 铁律（最高优先级）

1. **选材有钩子**：事件必须自带戏剧冲突或反常识落差，能一句话说清"哪里有意思"。
2. **观点先行**：每篇必须有清晰立场/判断，不骑墙，不"两方面都有道理"。
3. **历史真实**：核心史实必须可考；虚构/存疑处显式标注，不编造时间线与人名。
4. **打通当下**：事件与当下社会问题的连接必须是**显式的、具体的**，不许"值得深思"空话收尾。
5. **反 AI 味**：不用"值得注意的是""需要指出的是""总的来说，XX 为 YY 提供了 ZZ"。逐句检查。
6. **读者第一**：开头 3 句内必须让人知道"这事跟我有什么关系"。
7. **参考文献必带（硬性）**：**所有产出物**（公众号正文、微头条短文案）文末**必须**有「参考文献/资料来源」小节。
   - 公众号正文：文末列 2-4 条可靠来源（正史/传记/一手文献/权威二手），注明书/篇名、作者、责任者。
   - 微头条短文案：文末列 1-3 条可靠来源（如《三国志·魏延传》及裴松之注、《华阳国志》等）。
   - 引用史实、数据、观点时尽可能在文中或文末给出处；查不到可靠出处的内容**不下断言**，宁可标注存疑。
   - **格式（已踩坑·硬性）**：参考文献**不得用 markdown 有序列表**（`1. xxx`）。`markdown_to_wechat_doocs.py` 会把列表转成 `<ol>/<li>`，而**微信编辑器不认 `<ol>` 自动编号，且每个 `<li>` 会带 `margin-left:20px` 缩进**，导致正文里"编号乱、条条缩进、有空行"。**必须写成普通段落内、每条以分号分隔的纯文本**（微信稳定显示、顶格无缩进）。正确示例：
     ```
     ## 参考文献

     陈寿《三国志·蜀书·诸葛亮传》（刘备托孤"君可自取"、五次北伐、五丈原病逝等均出此），中华书局点校本；
     诸葛亮《前出师表》（"益州疲敝，此诚危急存亡之秋也"），载《三国志·诸葛亮传》裴松之注引《诸葛亮集》；
     房玄龄等《晋书·宣帝纪》（司马懿论"食少事烦"）。
     ```
   - **每条必须对应正文实际引用（已踩坑·硬性）**：不得为凑条数硬塞参考文献；正文没用到具体记载的典籍不要列入。**小说类**（如《三国演义》演义情节）不得与正史混列，除非正文明确标注"小说家言"且单独分类。
   - **引文出处精确到篇（已踩坑）**：同一作者多篇作品要区分（如诸葛亮《前出师表》"益州疲敝"与《后出师表》"鞠躬尽瘁，死而后已"**出处不同、篇名必须写对**，不得笼统写"《出师表》"）。
8. **小标题用 markdown ## 且极简（硬性）**：
   - **必须写 `## 序号 + 几个字`**（如 `## 01 反骨是假的`）：漏写 `##` 会变成普通段落，转 HTML 后**失去大字体和彩色下划线样式**（已踩坑，与 `news-social-writing` 同教训）。
   - 内容**极简**：序号 + 简短几个字高度概括，**忌长句/完整句子/文艺腔/过度解释**（示例：`01 压没被叫去开会`、`02 反骨是假的`、`03 谁写下的历史`、`1. 谣言比败仗致命`）。原则：一看就懂、不摆谱、像真人随手写的分节小标。禁学术腔、禁华丽对仗、禁过度解释。

## 五步工作流

### Step 1 选题
- 来源：真实历史事件、冷知识、人物轶事、被人遗忘的细节
- 筛选标准（至少中 3 条）：
  - 有冲突/反转/悬念
  - 能与一个**当代普遍焦虑**挂钩（内卷、信任、阶层、公平、孤独、职业、财富、AI、健康……）
  - 有具体人物或场景（好讲故事）
  - 能落一句让读者想转发的话（观点金句）
  - 史料可得、可核实
- 输出：一句话选题 + 目标社会问题 + 潜在金句（备用）

### Step 2 核实史料
- 交叉核对时间、地点、人名、关键数字
- 注明可用来源（正史/传记/一手文献/权威二手）——**并在写作阶段同步记录出处，供文末参考文献节使用**
- 标记不确定处：`〔存疑：……〕`
- 不要为了效果篡改史实细节
- **出处规则**：每个关键史实/数据/引文尽量落到具体来源（书名+篇名/卷次+作者）；无法核实者显式标注存疑，不下断言

### Step 3 拟定立意与结构
- 确认"这件事到底想说什么"——一句话主题句
- 结构（可选模板，勿死套）：
  1. 钩子开头：冲突场景/悬念/与读者相关的当下问题
  2. 事件还原：讲清来龙去脉，有人物有细节
  3. 转折/意外：事件里最反常识的点
  4. 映射当下：与某个现代问题显式对照
  5. 观点金句 + 开放思考（留给读者，不强行说教）
  6. **参考文献节（必带）**：文末独立成节，列出本文引用/参考来源
- 规划配图位（正文图片**宁缺毋滥**，常见 1 张即可，见下方配图规范）

### Step 4 撰写
- 遵循 SOUL.md 创作人格（内容创作者：有审美、有判断、写给人看）
- 语言：中文为主，术语保留原文；口语化但专业；长短句交替；留白
- 标题候选 3 个（见"标题规范"）
- 产出 `article.md`（Markdown）
- **小标题一律 `## 序号 + 几个字`（极简）**
- **文末必须带参考文献小节**（对应铁律 7，用"段落内分号+换行"格式，勿用 markdown 列表）
- **初稿产出后必须跑 AI 味终检**（见下方「AI 味终检」节）：调用 `scripts/ai_taste_check.py` 用强模型复核标题与正文，按报告修改后再交付

> ⚠️ **正文不得重复标题**：`article.md` 第一行**不要**写 `# 标题`。微信草稿的标题字段已单独设置，若在正文顶部再放一个 Markdown 一级标题，会转成 HTML 后**在正文最上方重复显示一遍标题**（已踩坑）。正文应从引言/钩子句直接开始，标题只用 `--title` 参数传入。

> ⚠️ **小标题必须写 `##`（已踩坑）**：小标题若只写 `01 谁写下的历史` 而不带 `## 前缀`，`markdown_to_wechat_doocs.py` 会把它当普通段落，导致**没有大字体、没有彩色下划线**，排版完全缺失。务必写成 `## 01 谁写下的历史`。

> ⚠️ **参考文献勿用列表（已踩坑）**：文末参考文献若用 `1. xxx` 有序列表，转 HTML 后是 `<ol>/<li>`，微信不认编号且 `li` 自带缩进，显示为"编号乱、条条缩进、有空行"。必须用**段落内分号分隔的纯文本**。发布后务必到微信后台核对参考文献排版。

### 配图与封面规范（已踩坑·重要）
- **正文图片宁缺毋滥**：别按"每 500 字 1 图"贪多。常见正文**只需 1 张图**（居中插入一处即可），插入数量**先跟用户对齐**；只有明确要图文并茂的题材才多放。正文主体仍是文字排版。
- **封面图片默认纯图不带字（已踩坑）**：封面**不要自作主张叠标题文字**——标题、副题等文字交给公众号封面库/标题字段（`--title`）呈现。若需叠字须先确认；不确认则用纯图。
- **AI 生成无字图**：若用 AI（如千问图像）生成人物/场景图，prompt 里明确写"画面中不要出现任何文字/汉字/题字/印章/签名/水印"，并用视觉模型（如 qwen3.8-max）看图确认确实无字、人物/要素完整、比例适合（横版）。
- **正文图引用必须无前缀路径（已踩坑·硬性）**：在 `article.md` 里写正文图用 `![说明](/tmp/xxx.jpg)`，**禁止 `file:///tmp/xxx.jpg`**。否则发布侧 `run_pipeline.py` 的 `_replace_local_images` 匹配不上，图引用原样进 HTML，微信草稿正文图=0（丢失）。写完自查 `grep -n 'file://' article.md` 应为空。
- **发布前验证封面非废图（已踩坑）**：AI 生图偶发产出 99% 全黑的废图（用户看到"几个横杠"）。用 PIL 检查 `dark=sum(hist[:85])/total*100`，`dark>90%` 即废图，须重新生成，不能将就。

### Step 4.5 AI 味终检（强模型复核 · 硬性）

> **初稿写完不允许直接交付**。必须先用独立强模型（默认 `kimi-k3`）做一遍"挑刺式"终检，重点抓标题 AI 味与正文套话，改完再进发布流程。

**用法：**
```bash
python3 skills/history-social-writing/scripts/ai_taste_check.py <article.md> '标题候选1' '标题候选2' '标题候选3'
```

- 脚本从 `~/.openclaw/openclaw.json` 的 `custom_go`（opencode）provider 真实读取 key，走 curl 调用（urllib 会被 Cloudflare 拦）
- 检查项：① 标题 AI 味评级（高/中/低）+ 改写建议；② 正文套话/空修饰/排比空转/强行升华/翻译腔扫描；③ 史实表述疑点；④ 是否建议返工
- 模型可换：用 `--model <id>` 参数切换（不用改脚本），默认 kimi-k3，备用 glm-5.3、deepseek-v4-flash；kimi-k3 实测对史实硬伤（如"纸上谈兵"典出赵括而非马谡）也能抓出
- **改稿闭环（硬性）**：报告里命中高/中 AI 味的标题、命中项段落，**必须按建议改写后重新跑一遍终检，直到报告不再有高/中 AI 味命中才允许交付**（循环：检查 → 修改 → 再检查 → 通过）；若同一问题两轮都改不掉，换模型（如 glm-5.3）复核或人工介入
- **多模型交叉验证（2026-08-22 赵云文实战）**：单模型会漏检/误报。史实类"疑点"不要盲改，先搜证确认（如检查器误报"长坂坡救主不在正传"，搜证确认在《三国志·赵云传》正文，没改）。kimi-k3/glm-5.3 都误判过"赵云生前没封侯"，是 deepseek-v4-flash 抓出真相（封永昌亭侯），交叉验证能抓到单个模型漏掉的硬伤
- **上游抖动处理（2026-08-22 实战）**：kimi/glm/deepseek 都间歇性返回 Internal server error，重试或换 `--model` 即可；短请求探测正常不代表长请求（正文4000字）不超时
- **输出控制（已踩坑）**：检查器 prompt 已内置"直接给结论、不展示思考过程、总输出≤600字"，模型若把思考过程写出来会撑爆输出额度导致报告截断，重跑即可

### Step 5 交付
- 交发布侧 `wechat-article-publisher` skill 处理：压图、传素材、转 HTML、存草稿
- 归档到 `articles/published/`
- **同步产出微头条短文案**：每篇公众号文章交付时，额外生成一份适配今日头条「微头条」的短文案，随草稿一起交付给用户，由用户手动粘贴发布（不做头条自动发布）。

## 微头条短文案规范（随公众号文章同步产出）
- 定位：单条微头条，独立可读，不依赖公众号全文
- **不提公众号**：微头条文案首尾都不要出现公众号名/公众号引流（用户明确要求）
- **参考文献（硬性必须）**：文末**必须**列 1-3 条可靠来源（如《三国志·魏延传》及裴松之注、《华阳国志》等），增加可信度与历史感
- 结构：钩子开场（1 句）+ 事件核心（2-4 句）+ 一句观点/金句收尾 + 参考文献（文末）
- 长度：建议约 **800 字**（用户偏好）
- 风格：口语化、有立场、留互动钩子（可问读者一句，引导评论）
- 可选配图：若有可用图（如人物照）可附，不加也完全 OK
- 与正文关系：提炼精华／换个角度切，不必照搬；可加"想看完整版可看公众号"收尾（可选）
- 产出物：每篇存一份 `articles/toutiao/YYYYMMDD_人物_微头条.txt`，并在交付时把文案直接发到对话，方便复制

## 标题规范
- 有信息量，杜绝"历史启示录""不得不看的道理"这类空泛格式
- 好用：悬念式、反差式、数字式、对话式、代入式（"如果你……你会怎么选"）
- 3 个候选，分别是：悬念型 / 反差型 / 代入型
- 不超过 20 字为佳，留有余地

> ⚠️ **小标题（正文内 ## ）要极简**：正文小标题**不要**用长句/完整句子/文艺腔（如"一个人的‘造反’，其实是他没被叫去开会"——这类有 AI 味、读着像刻意凑的）。统一用**`## 序号 + 简短几个字`高度概括**，例如：`## 01 压没被叫去开会`、`## 02 反骨是假的`、`## 03 谁写下的历史`、`## 1. 谣言比败仗致命`。原则：一看就懂、不摆谱、像真人随手写的分节小标。禁学术腔、禁华丽对仗、禁过度解释。**必须带 `##` 前缀**，否则无样式。
- 全文小标题风格保持一致（统一用数字序号开头，或统一不用）。

## 反翻译腔 + 反 AI 味 L4 终检清单
- [ ] 无"值得注意的是/需要指出的是/总的来说/值得一提的是"
- [ ] 无"丰富的/强大的/灵活的"式空修饰
- [ ] 无句句排比无实义
- [ ] 每段有判断或信息，不空转
- [ ] 结尾不强行升华，给行动/思考，不喊口号
- [ ] 标题不过度承诺（不割韭菜式）
- [ ] **已跑 AI 味终检（`ai_taste_check.py`，kimi-k3 复核）**，命中项已按报告改写，标题无高 AI 味残留
- [ ] **正文第一行不是 `# 标题`**（标题走 `--title` 参数，不写进正文，避免顶部重复）
- [ ] **小标题均已写 `## 序号 + 几个字` 且极简**（非长句、非文艺腔、非 AI 味；漏 `##` 会失去大字+彩色下划线样式）
- [ ] **文末已附「参考文献/资料来源」小节**，且**用段落内分号+换行格式（非 markdown 列表）**；每条对应当前正文实际引用，无硬凑条数、无小说与正史混列、篇名精确
- [ ] **封面默认纯图不带字**（文字交封面库/标题字段；AI 图须无字版并已看图验证）
- [ ] **正文图片宁缺毋滥、常见 1 张**（数量已跟用户对齐）
- [ ] **正文图引用无 `file://` 前缀**（用 `](/tmp/xxx.jpg)`；`grep -n 'file://' article.md` 应为空）
- [ ] **封面/正文图已验证非废图**（dark≤90%，非 99% 全黑；AI 图已用视觉模型确认有内容）
- [ ] 发布到微信草稿后**核对参考文献排版**（微信不认 `<ol>` 编号，列表会乱）

## 内容红线
- 不虚构史实；存疑线须标注
- 不涉及政治敏感、不影射违规内容、不抹黑特定群体
- 涉及历史评价尽量有史家依据，避免独断偏激
- **出处不明不下断言**：无法给出可靠来源的关键史实/数据/引文，须标注存疑或删去，不得硬写
- 保持跟公众号定位（棱镜折射）一致：讲人、讲事、讲理，不贩卖焦虑、不标题党欺诈

## 与现有 skill 的衔接
- 本 skill 只负责**写作**（Step 1-4）
- **发布**（压图/传素材/转HTML/存草稿）交给 `wechat-article-publisher`（参考其 SKILL.md 的六步流水线）
