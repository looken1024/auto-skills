# news-social-writing —— 当代新闻×社会问题公众号写作

面向公众号「棱镜折射」及其他新闻社会类内容。核心公式：

**一条新闻事件 → 一个当下社会问题 → 引发共鸣与思考 → 驱动转发/关注**

> 本 skill 参照 `history-social-writing` 构建，定位从「历史」切换为「当代新闻/社会热点」。核心差异：素材来自**当下新闻事件**（时效性强、需核实最新事实），观点输出更贴近眼前社会情绪。**文末必带信息来源**沿用为硬性铁律。

## 定位与读者

- 公众号：棱镜折射（未认证订阅号、主体个人）
- 目标：涨粉、阅读量、转发、关注
- 读者：泛大众，非新闻专业，但关注时事、喜欢「看得懂 + 有共鸣 + 有观点」
- 文风：有观点、口语化、反 AI 味，反对空转与标题党
- 时效：跟进当日/近期热点，抢在话题退温前产出

## 铁律（最高优先级）

1. **选材有钩子**：事件必须自带冲突、反转或反常识落差，能一句话说清"哪里有意思"。
2. **观点先行**：每篇必须有清晰立场/判断，不骑墙，不"两方面都有道理"。
3. **事实真实**：核心事实（人物、时间、地点、数字、经过）必须可考、可溯源；未经核实的信息**不下断言**，显式标注"据报/存疑"。
4. **打通当下**：事件与读者处境的连接必须**显式、具体**，不许"值得深思"空话收尾。
5. **反 AI 味**：不用"值得注意的是""需要指出的是""总的来说，XX 为 YY 提供了 ZZ"。逐句检查。
6. **读者第一**：开头 3 句内必须让人知道"这事跟我有什么关系"。
7. **信息来源必带（硬性）**：**所有产出物**（公众号正文、微头条短文案）文末**必须**有「信息来源/参考资料」小节。
   - 公众号正文：文末列 2-4 条来源（媒体名称、报道标题、日期；如《人民日报》、新华社、澎湃新闻、财新等；必要时附链接），结尾前单独成节。
   - 微头条短文案：文末列 1-3 条来源。
   - 关键事实、数据、引文尽可能文中或文末给出处；查不到可靠来源的**不下断言**，宁可标注存疑。
   - **格式（已踩坑·硬性）**：文末来源**不得用 markdown 有序列表**（`1. xxx`）。`markdown_to_wechat_doocs.py` 会把列表转成 `<ol>/<li>`，而**微信编辑器不认 `<ol>` 自动编号，且每个 `<li>` 会带 `margin-left:20px` 缩进**，导致正文里"编号乱、条条缩进、有空行"。**必须写成普通段落内、每条以分号或换行分隔的纯文本**（微信稳定显示、顶格无缩进）。正确示例（每条后换行，段内用 `；` 或换行分隔均可，勿用 `1.` 列表）：
     来源：
     凤凰网《北京化工大学实验室发生安全事故，有学生受伤》（大河报豫视频，2026-08-06）；
     联合早报《北京研究生凌晨实验炸断手指，内部通报称"擅自违规"被批卸责》（2026-08-07）。
   - **每条必须对应正文实际引用（已踩坑·硬性）**：不得为凑条数硬塞来源；正文没用的来源不要列。**单一信源的关键论断**需标注存疑（如"断五接二失三"这类网传细节，无权威信源时必须标"存疑"）。小说/演义类素材（如有）不得与新闻/正史混列，须单独标注。
8. **标题三候选（硬性）**：**每篇交付时必须给出 3 个候选标题**（悬念型 / 反差型 / 代入型各 1），不得只给单个标题。由用户选定后，最终标题走 `--title` 参数入库，正文不写标题。
9. **小标题用 markdown ## 且极简（硬性）**：
   - **必须写 `## 序号 + 几个字`**（如 `## 01 发生了什么`）：漏写 `##` 会变成普通段落，转 HTML 后**失去大字体和彩色横线样式**（已踩坑，见下）。
   - 内容**极简**：序号 + 简短几个字高度概括，**忌长句/完整句子/文艺腔/过度解释**（对齐历史版规范，示例：`01 一纸通报`、`02 舆论为何炸`、`03 凌晨的实验室`）。原则：一看就懂、不摆谱、像真人随手写的分节小标。

## 封面模板（新闻版专属 · 硬性参考）

> 每篇公众号文章**必须**有封面（微信草稿强制）。新闻版统一使用以下视觉模板，保证账号封面风格连贯。生成方式：PIL 程序化作图（中文字体用 Noto Serif CJK Bold），或由图像类 skill 按同一规范生成。

**固定参数：**
- 尺寸：**900 × 383**（约 2.35:1，公众号主封面比例），JPEG、quality 88、≤ 800KB
- 底色：深蓝渐变 `RGB(15,32,56)` → 自上而下加深（`shade = 56 - 28*(i/H)`）
- 版式（从上到下、左对齐）：
  1. 顶部小标签：栏目名（如「社会观察」「热点追踪」），字号 28，色 `RGB(120,180,255)`
  2. 主标题：一句话点题，字号 52，白色 `RGB(255,255,255)`，可换行，不超过 20 字
  3. 副标题：事件核心冲突（如「受伤学生 vs 校方通报」），字号 30，色 `RGB(200,210,230)`
- 装饰元素（右下角）：一个警示/聚焦符号——橙色 `RGB(255,180,60)` 三角 + 内嵌感叹号，标示"新闻/警示"属性
- 风格：克制、新闻感、不花哨。避开与历史版（暖色/文字海报）雷同的版式

> ⚠️ **封面尺寸随用户偏好可调**：若用户明确要求匹配历史版（如姜维/吕布的 900×500 深灰蓝底），按用户指定规格执行（本 skill 默认 900×383 深蓝；历史版为 900×500 深灰蓝）。生成前先确认用户是否指定了封面样式。

> ⚠️ **封面默认纯图不带字（已踩坑·重要）**：新闻版模板是"文字海报"式（版式自带标题字），但**用 AI 图片作封面时**，若用户要"纯图",则**封面图片本身不带任何叠加文字**——标题交给公众号封面库/标题字段呈现，不要自作主张在 AI 图上叠标题字（须先确认）。用 AI 图作封面时：
> 1. **先生成无文字图**：prompt 明确"画面中不要出现任何文字/汉字/印章/签名/水印"
> 2. **先让视觉模型看图验证**（人物/主体完整、无字、横版适合）
> 3. 图内已有题字/印章而用户不要时，**重新生成无字版**，勿直接裁（可能裁到人或留字）
> 4. 若最终叠字，深色图用浅字、浅色图用深字，避开图内文字与人脸
> 5. 裁切保主体（头顶留天头，防二次裁切）

> ⚠️⚠️ **从新闻页抓素材图，必须验证画面内容（已踩坑·硬性）**：写新闻类文章配图时，常用**新闻报道里的真人现场图**。**绝不能用网页文字描述推断图片内容**——坑：某篇写郑国霖景区打工的文章，文字提到"拉黄包车"，就假设抓到的配图是拉黄包车场面，实际抓下来却是**另一张古装剧剧照**（两个人对视），封面/正文图全用错，被用户识破。**拿到网图后必须用千问视觉模型（qwen-vl-max）识图验证**：是不是我以为的那个画面/人物？有无文字水印？有"头条@xx""XX时报"等水印须裁掉（裁前让视觉模型给主体坐标，别裁到人）；新闻图常带顶部白边/底部字幕，注意甄别。**这是每个配图的强制动作，不是可选**。

**流程（Step 5 交付时）：**
- 按模板生成封面 → 走 `wechat-article-publisher` 的 `run_pipeline.py --cover` 压缩上传
- 归档到 `articles/covers/YYYYMMDD_主题_cover.jpg`

## 五步工作流

### Step 1 选题
- 来源：当日/近期新闻热点、社会事件、政策变化、行业动态、人物新闻
- 筛选标准（至少中 3 条）：
  - 有冲突/反转/悬念
  - 能与一个**当代普遍焦虑**挂钩（内卷、信任、健康、公平、职业、财富、AI、教育、养老……）
  - 有具体人物或场景（好讲故事）
  - 能落一句让读者想转发的话（观点金句）
  - 事实来源充分、可核实
- 输出：一句话选题 + 目标社会问题 + 潜在金句（备用）

### Step 2 核实事实
- **多方交叉核对**：至少 2 个独立信源核对时间、地点、人物、数字、经过
- 注明可用来源（权威媒体/官方通报/一手采访/权威平台）
- 标记不确定处：`〔据报：……〕` 或 `〔存疑：……〕`，不把传闻当事实
- 同步记录来源清单，供文末信息来源节使用
- 不要为了效果夸大、扭曲或张冠李戴

### Step 3 拟定立意与结构
- 确认"这件事到底想说什么"——一句话主题句
- 结构（可选模板，勿死套）：
  1. 钩子开头：冲突场景/悬念/与读者相关的当下问题
  2. 事件还原：讲清来龙去脉，有人物有细节、有时间线
  3. 转折/意外：事件里最反常识的点
  4. 映射当下：与某个现代问题显式对照
  5. 观点金句 + 开放思考（留给读者，不强行说教）
  6. **信息来源节（必带）**：文末独立成节，列出本文引用来源
- 规划配图位（正文图片**宁缺毋滥**，常见 1 张即可）

### Step 4 撰写
- 遵循 SOUL.md 创作人格（内容创作者：有审美、有判断、写给人看）
- 语言：中文为主，术语保留原文；口语化但专业；长短句交替；留白
- 标题候选 3 个（悬念型/反差型/代入型，见「标题规范」）——**交付时必须一并给出**
- 产出 `article.md`（Markdown）
- **小标题一律 `## 序号 + 几个字`（极简）**
- **文末必须带信息来源小节**（对应铁律 7，用"段落内分号/换行"格式，勿用 markdown 列表）
- **初稿产出后必须跑 AI 味终检**（见下方「AI 味终检」节）：调用 `scripts/ai_taste_check.py` 用强模型复核标题与正文，按报告修改后再交付

> ⚠️ **正文不得重复标题**：`article.md` 第一行**不要**写 `# 标题`。微信草稿的标题字段已单独设置，若在正文顶部再放一个 Markdown 一级标题，会转成 HTML 后**在正文最上方重复显示一遍标题**（已踩坑）。正文应从引言/钩子句直接开始，标题只用 `--title` 参数传入。

> ⚠️ **小标题必须写 `##`（已踩坑）**：小标题若只写 `01 一纸通报` 而不带 `## 前缀`，`markdown_to_wechat_doocs.py` 会把它当普通段落，导致**没有大字体、没有彩色横线**，排版完全缺失。务必写成 `## 01 一纸通报`。

> ⚠️ **信息来源勿用列表（已踩坑）**：文末来源若用 `1. xxx` 有序列表，转 HTML 后是 `<ol>/<li>`，微信不认编号且 `li` 自带缩进，显示为"编号乱、条条缩进、有空行"。必须用**段落内分号分隔的纯文本**。发布后务必到微信后台核对。

### Step 4.5 AI 味终检（强模型复核 · 硬性）

> **初稿写完不允许直接交付**。必须先用独立强模型（默认 `kimi-k3`）做一遍"挑刺式"终检，重点抓标题 AI 味与正文套话，改完再进发布流程。

**用法：**
```bash
python3 skills/news-social-writing/scripts/ai_taste_check.py <article.md> '标题候选1' '标题候选2' '标题候选3'
```

- 脚本从 `~/.openclaw/openclaw.json` 的 `custom_go`（opencode）provider 真实读取 key，走 curl 调用（urllib 会被 Cloudflare 拦）
- 检查项：① 标题 AI 味评级（高/中/低）+ 改写建议；② 正文套话/空修饰/排比空转/强行升华/翻译腔扫描；③ 事实表述疑点；④ 是否建议返工
- 模型可换：用 `--model <id>` 参数切换（不用改脚本），默认 kimi-k3，备用 glm-5.3、deepseek-v4-flash；kimi-k3 实测对史实硬伤（如"纸上谈兵"典出赵括而非马谡）也能抓出
- **改稿闭环（硬性）**：报告里命中高/中 AI 味的标题、命中项段落，**必须按建议改写后重新跑一遍终检，直到报告不再有高/中 AI 味命中才允许交付**（循环：检查 → 修改 → 再检查 → 通过）；若同一问题两轮都改不掉，换模型（如 glm-5.3）复核或人工介入
- **多模型交叉验证（2026-08-22 赵云文实战）**：单模型会漏检/误报。史实类"疑点"不要盲改，先搜证确认（如检查器误报"长坂坡救主不在正传"，搜证确认在《三国志·赵云传》正文，没改）。kimi-k3/glm-5.3 都误判过"赵云生前没封侯"，是 deepseek-v4-flash 抓出真相（封永昌亭侯），交叉验证能抓到单个模型漏掉的硬伤
- **上游抖动处理（2026-08-22 实战）**：kimi/glm/deepseek 都间歇性返回 Internal server error，重试或换 `--model` 即可；短请求探测正常不代表长请求（正文4000字）不超时
- **输出控制（已踩坑）**：检查器 prompt 已内置"直接给结论、不展示思考过程、总输出≤600字"，模型若把思考过程写出来会撑爆输出额度导致报告截断，重跑即可

### Step 5 交付
- **生成封面**：按「封面模板」规范生成 `articles/covers/YYYYMMDD_主题_cover.jpg`（若用户指定样式，按指定规格；AI 图封面默认纯图无字，文字交标题字段）
- 交发布侧 `wechat-article-publisher` skill 处理：压图、传素材、转 HTML、存草稿
- 归档到 `articles/published/`
- **同步产出微头条短文案**：每篇公众号文章交付时，额外生成一份适配今日头条「微头条」的短文案，随草稿一起交付给用户，由用户手动粘贴发布（不做头条自动发布）。

## 微头条短文案规范（随公众号文章同步产出）
- 定位：单条微头条，独立可读，不依赖公众号全文
- **不提公众号**：微头条文案首尾都不要出现公众号名/公众号引流（用户明确要求）
- **信息来源（硬性必须）**：文末**必须**列 1-3 条可靠来源（媒体名+报道标题/日期），增加可信度
- 结构：钩子开场（1 句）+ 事件核心（2-4 句）+ 一句观点/金句收尾 + 信息来源（文末）
- 长度：建议约 **800 字**（用户偏好）
- 风格：口语化、有立场、留互动钩子（可问读者一句，引导评论）
- 可选配图：若有可用图（新闻图/示意图）可附，不加也完全 OK
- 与正文关系：提炼精华／换个角度切，不必照搬；可加"想看完整版可看公众号"收尾（可选）
- 产出物：每篇存一份 `articles/toutiao/YYYYMMDD_主题_微头条.txt`，并在交付时把文案直接发到对话，方便复制

## 标题规范
- 有信息量，杜绝"这件事告诉我们""值得所有人警惕"这类空泛格式
- 好用：悬念式、反差式、数字式、对话式、代入式（"如果发生在你身上……"）
- **3 个候选必须都给**，分别是：**悬念型 / 反差型 / 代入型**（对标历史版的标题规范，交付时一并列出供用户挑选）
- 不超过 20 字为佳，留有余地

> ⚠️ **小标题（正文内 ## ）要极简**：正文小标题**不要**用长句/完整句子/文艺腔。统一用**`## 序号 + 简短几个字`高度概括**，例如：`## 01 发生了什么`、`## 02 谁在表态`、`## 03 跟你有什么关系`。原则：一看就懂、不摆谱、像真人随手写的分节小标。禁学术腔、禁华丽对仗、禁过度解释。**必须带 `##` 前缀**，否则无样式。
- 全文小标题风格保持一致（统一用数字序号开头，或统一不用）。

## 反翻译腔 + 反 AI 味 L4 终检清单
- [ ] 无"值得注意的是/需要指出的是/总的来说/值得一提的是"
- [ ] 无"丰富的/强大的/灵活的"式空修饰
- [ ] 无句句排比无实义
- [ ] 每段有判断或信息，不空转
- [ ] 结尾不强行升华，给行动/思考，不喊口号
- [ ] 标题不过度承诺（不割韭菜式）
- [ ] **已跑 AI 味终检（`ai_taste_check.py`，kimi-k3 复核）**，命中项已按报告改写，标题无高 AI 味残留
- [ ] **已给出 3 个候选标题（悬念/反差/代入）供用户挑选**
- [ ] **已按新闻版封面模板生成封面**（900×383 深蓝渐变 + 大标题 + 警示元素；若用户指定样式则按其规格；用 AI 图须先看图验证+避让文字/人脸+注意明暗对比；**用户要纯图则封面不带字**）
- [ ] 正文第一行不是 `# 标题`（标题走 `--title` 参数，不写进正文，避免顶部重复）
- [ ] **小标题均已写 `## 序号 + 几个字` 且极简**（非长句、非文艺腔、非 AI 味；漏 `##` 会失去大字+横线样式）
- [ ] **文末已附「信息来源/参考资料」小节**，且**用段落内分号/换行格式（非 markdown 列表）**；每条对应当前正文实际引用，无硬凑条数，单一信源的关键论断已标"存疑"
- [ ] **正文图片宁缺毋滥、常见 1 张**（数量已跟用户对齐）
- [ ] 发布到微信草稿后**核对信息来源排版**（微信不认 `<ol>` 编号，列表会乱）

## 内容红线
- **事实优先**：未经多重核实的传闻不作文；关键事实标"据报/存疑"
- 不虚构、不夸大、不标题党欺诈
- 不涉及政治敏感、不传谣言、不抹黑特定群体
- 涉及争议事件尽量给出多方视角与信息来源，避免独断偏激
- 保持跟公众号定位（棱镜折射）一致：讲人、讲事、讲理，不贩卖焦虑、不消费悲剧

## 与现有 skill 的衔接
- 本 skill 只负责**写作**（Step 1-4），素材核实走联网搜索/web_fetch
- **发布**（压图/传素材/转HTML/存草稿）交给 `wechat-article-publisher`（参考其 SKILL.md 的六步流水线）
- **封面**：按本 skill「封面模板」规范生成，再走发布侧压缩上传
- 若需封面配图，用图像类 skill 生成（**无字版**）/搜索，再走发布侧压缩上传
- 姊妹 skill：`history-social-writing`（历史类），二者共用发布链路与写作风格，但封面色板/版式各不相同（新闻=深蓝+警示，历史=暖色+文字海报）
