# Pexels 图集流水线：话题池枯竭 → 换池/扩充

> 沉淀自 2026-09-14 图集任务排障（job 9d58e7843134，44 轮中 4 次失败）+ 2026-10-01/02 两次换池实操。

## 症状

- 非全量失败：一天几十轮里零星 4 次挂，报 `去重后有效图片不足3张（仅0/1张，剔除33-36张重复）`。
- 失败轮次的话题全是老牌话题（大海、鸟类、日出、城市夜景）。

## 根因

md5 台账已积累数千张已发图。Pexels 单话题检索深度有限（per_page*4 ≈ 36 张候选），话题历史消耗 ≈ 检索深度时，搜回来的几乎全是发过的重复图 → 去重后凑不够 3 张 → 整轮放弃。旧选题逻辑只做「当天不重复」，不管话题的历史总消耗，所以会反复撞枯竭话题。

## 修复（pexels_gallery_draft.py）

- `TOPIC_EXHAUSTED = 30`：单话题累计已发 ≥30 张视为检索池吃穿。
- `load_topic_usage(ledger)`：从台账 `md5s` 统计每话题已发数（`Counter(v.get("topic") ...)`）。
- 选题时：当天去重 → **再按台账用量排除枯竭话题** → 随机只在剩余里选；全枯竭才放宽并打日志。
- 验证：语法检查 + `--dry-run` 实跑两轮，选中低用量话题、正常产出 9 张。

## 补丁自摆乌龙教训

第一版补丁里 `load_topic_usage(sent)` 引用了**还没赋值**的变量（sent 在后面几行才定义），dry-run 立刻 `UnboundLocalError`。教训：**台账/状态读取函数在 main 里调用点要确认变量作用域**；有 `--dry-run` 模式的脚本，补丁后必跑一次 dry-run 验证——一次就抓住了，没污染线上班次。

## 什么时候该换池（阈值信号）

`TOPIC_EXHAUSTED` 只是“单个话题不用了”，整个池子全超阈值时会反复打日志 **`所有候选话题均已发 ≥30 张，放宽限制`**——那就是该换池了。验证性的信号：换池后一轮 `dup_skipped: 0`（全是新图）。

## 换池/扩充工作流（已验证）

1. **列候选**：按同一类目（自然景观/建筑/世界地标古迹/人文生活/夜市）拟一批新词，中文名 + 英文检索词成对。
2. **API 探活**：`/v1/search?query=<en>&per_page=8~15&orientation=landscape`，计 `len(photos)`。**免费额度 200 次/小时，别全量打**；抽查要留额度给线上班次。
3. **相关性抽查（必做，别只看条数）**：打印 `photos[].alt` + `photos[].url` 人工确认“图是不是这个东西”。地名/文物类英文词容易跑偏：
   - `dong drum tower` → 返北京/西安鼓楼（不是侗寨）→ 改 `dong minority village guizhou`
   - `xiapu mudflat` → 返通用海滩 → 改 `xiapu china fishing`
   - `sera monastery tibet`（色达）/ `kaiping diaolou`（开平碉楼）→ 没有对口图，**直接弃用，别硬凑**（挂羊头卖狗肉比少两条更糟）
   - 偏瘦的换更常见的同义写法：`birch forest`(2) → `white birch trees forest`(8)
4. **落盘两处**：`scripts/topics.json`（脚本优先读它，格式必须是 `[{"cn":…,"en":…}, …]`）**和** `_BUILTIN_TOPICS`（兜底），两边保持一致。
5. **验证加载**：`python3 -c "import pexels_gallery_draft as g; print(len(g.TOPICS))"`，并确认新增的在内、故意弃用的不在。
6. **实跑一轮**：看 `topic` 是不是新词、`dup_skipped` 是否归零。

### 坑：`topics.json` 的格式不匹配会静默失效

曾有版本存成 `[["cn","en"], …]` 数组，而 `load_topics()` 按 dict 读（`d.get("cn")`）→ 抛 `AttributeError: 'list' object has no attribute 'get'` → 被 `except` 吃掉、**静默回退内置表**，于是这个文件长期形同虚设（日志里只有一句 `! 读取 topics.json 失败(...)，回退内置列表`，很容易被忽略）。
修法：`load_topics()` 同时兼容 dict 和 `[cn, en]` 两种，并在换池后实测 `g.TOPICS` 是否真的来自 json。

## 通用化

任何「随机选题 + 历史去重台账」的流水线都会有同样的枯竭曲线：选题决策必须消费台账统计（不只是过滤），给每个候选打「历史消耗量」标签，超阈值排除。台账越大这条越重要。

同理，**任何“中文名 → 英文检索词”的映射表都必须做相关性抽查**：能搜出结果只证明索引里有词，不证明图对。
