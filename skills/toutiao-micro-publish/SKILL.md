# 今日头条微头条流水线（热搜 → 文章 → 复审 → 发布 → 异常通知）

用户要求的每日内容生产流程。给定"写一条今日头条微头条"，自动走完：抓热搜 → 筛选题 → 抓原文核事实 → 口语化重写 → **高级模型复审（通过才发布）** → 浏览器辅助发布 →（异常时邮件通知）。

## 触发场景
- "帮我写条微头条" / "今日头条发一条"
- "今天有什么热搜能写"
- "按老流程出条微头条发到头条"
- "深度单篇" / "把XX写深写透" / "长文微头条"（走下方"深度单篇产线"，写前先选题→设计结构→逐部分写）

> 调度：快讯流 cron（每2小时）+ 深度单篇 cron（每日 09:00，独立任务 toutiao-deep-article）。见文档底部"调度说明"。

## 流程（7 步）

### Step 1 抓当天热搜
优先用 tavily_search/web_search 查"今日热搜 微博热搜榜"（topic=news, time_range=day），或 opencli 抓微博/百度热搜榜。
多家交叉看，别只看一家（微博热搜偏娱乐、百度偏社会，综合取）。

### Step 2 筛选题（用户规则 · 硬性）
**多候选机制（2026-08-25 用户要求）**：每次至少筛 **3-5 个候选选题**，按优先级排序（高共鸣 > 硬数据 > 反差）。候选逐一过查重，命中已发布/同主题 → 直接换下一个候选，**不存在“这个撞了就只能硬发或发完再删”**。新闻源多的是，选不出来就回 Step 1 重新抓热搜，不要单条选题硬刚查重。
候选必须同时满足：
0. **查重（2026-08-24 用户铁律）**：先查历史发过哪些，**同主题/同事件/同角度的选题一律不选**，哪怕换了个切入口。查重渠道（按顺序）：① **本地台账 `logs/published.log`**（每次发布成功/失败都追加，cron 隔离会话直接读文件，最可靠）② 作品管理页列表（mp.toutiao.com 已发布+审核中，近 7 天为主，重点看今天）③ skill 存档 examples/ 目录 ④ 同话题标签在今日热搜里是否连续多日霸榜（连续霸榜多为老帐重提，易撞）
   **双渠道必查（2026-08-25 撞车教训）**：台账和作品管理页**两个渠道都必须扫**，不能只查台账。若发现作品管理页有而台账无的内容 → **先补记台账再定题**，防止台账漏记导致误判。
   **查重结果必须带进发布确认**：查重结论（"台账已查 N 条 / 作品管理页已查 M 条，无同主题"）必须写进 Step 6 的发布前用户确认消息，没有查重清单就不允许点发布。
   判断标准：同一事件主体 + 同一核心争议/事实 = 重复，直接跳过换题；仅当事件有新进展（如官方下场/新处置结果/新当事人发声）才算增量，但增量不足时仍不选
   已踩坑（2026-08-24）：① 18:06 敌敌畏撞 16:22（同主题同事件，后者已发布）② 20:08 甲醛白菜撞 8/23（只查了 examples 存档没查发布历史）→ 单条选题时必查这两处
   已踩坑（2026-08-25）：③ 星宇股份撞车——台账漏记（发布页有、台账无）导致发布后才发现删除；④ 单条选题模式导致撞车后无候选可换、硬发。→ 双渠道必查 + 多候选备选，两条一起治
1. **不碰政治**（涉政、涉民族敏感、涉国际冲突一律跳过）
2. **有具体事件落地**（有清晰的时间/地点/人物/事件，不是纯观点口水仗）
3. **大众有共鸣**（能戳中普遍情绪：打工、涨薪、选择、公平、教育、健康、消费）
加分项：有反差/反转（"当初劝他捞钱，如今打脸"这类）、有具象数字、有人物原话。
已验证高共鸣主题类型（2026-08-24 用户补充）：食品安全、反诈、职场坑、消费坑——这类民生痛点自带情绪，素材越实（具体公司名/人名/金额/原话）越能写出人味。

已踩坑示例：丁真爆红6年（2026-08-23 采用）——有"3500月薪 vs 年薪七位数""6年""近4000万文旅收入"等硬数字，有杜冬、"你觉得我是本色出演吗"原话，反差拉满。白鹿相扑上衣、综艺明星微表情这类纯娱乐甜点流量但无社会共鸣，次选。

### Step 3 抓原文 + 核事实（web_fetch）
- 用 web_fetch 抓报道原文（首选一手：官方通报/权威媒体；次选门户转载）
- **提取三样东西**：核心事实（时间/地点/人物/经过）、关键数字、人物原话（直接引语）
- 至少 2 个独立信源核对关键数字/断言；单个信源的网传细节标"据报/存疑"
- 不为了效果夸大、扭曲、张冠李戴

### Step 4 写作（400-500 字 · 风格硬性）
用户风格铁律，逐条自查：
- **400-500 字**（计数含标点；超了删修饰语压回来）
- **口语化短句**：句子短、有节奏，像饭桌闲聊，不像新闻通稿
- **有情绪、有态度、有反讽**：立场鲜明，可阴阳怪气；不骑墙、不"两方面都有道理"
- **夹方言感**：适度点缀（巴适得很 / 哦豁 / 绝了 / 憋 / 整），不滥用、不硬凹，选词贴近话题地域
- **数字和细节具体化**："月薪3500""俩小时一千万播放""2024年八·一赛会带动近4000万"——拒绝"很多钱""大量网友"
- **不用 AI 惯用语**：抛掉"近日""随着""引发广泛关注""值得注意的是""这一事件""背后""映射了"这类词
- **禁用短视频套路梗/网感短句（2026-08-26 用户点名·硬性）**："正在偷你的底裤""套路就三样""翻译成人话""翻翻名单，个个都是人才""这事离谱在哪""一个比一个会玩""谁懂啊""绝了"这类刻意设计的"短小精炼金句"是重灾区——看似口语、实则堆砌网感，比套话更 AI 味。口语化要自然平实，像普通人说话，不靠梗句撑场；一段话里出现两处以上这种句式直接返工。
- **一篇只说一个核心观点（用户铁律·2026-08-24）**：像跟人聊天，说完就停，留白比说透更有力；不面面俱到，不贪多。选材时也按此取舍：宁要一个事件说透，不要三件事蜻蜓点水。
- **结尾二选一**：抛个问题让评论区炸（现有写法）**或**给个实用建议让读者觉得有用（如"下馆子先看消杀资质"）；不要"总而言之/综上所述"式收尾
- 结构参考（已验证）：钩子开头（反差/数字/画面）→ 事件还原（带原话）→ 反差点 → 观点/反讽 → 开放问题。
- 标题：微头条一般无标题，直接正文；可加话题标签 `#话题#` 增加曝光（可选）

### Step 4.5 高级模型复审（硬性 · 用户 2026-08-23 要求）

**初稿出来后、发布前，必须用独立高级模型 review 一遍，通过才允许进发布。** 脚本：`scripts/review_weitoutiao.py`

```bash
python3 scripts/review_weitoutiao.py <文案.txt> [--model glm-5.3] [--strict]
```

- **默认模型 glm-5.3**（高级模型，从 openclaw.json 的 custom_go provider 读 key，curl 调用）
- 备选：`--model deepseek-v4-pro` / `minimax-m3` / `qwen3.8-max`（上游抖动时切换）
- `--strict` 宁严勿松

**检查项：**
一、AI 味扫描：① 套话开头（近日/随着/引发广泛关注/值得注意的是）② 空泛修饰（丰富的/深刻的/很多钱/大量网友）③ 排比空转 ④ 强行升华结尾 ⑤ 新闻通稿腔（"这一事件""带动XX经济""背后折射出"）⑥ 不口语化书面词（竟然/堪称/可谓滥）
二、可完善点：开头钩子抓不抓人、原话/数字用没用足、方言感自然还是硬凹、结尾够不够勾评论、有没可删废话句
三、结论：是否建议返工（是/否）

**闭环（硬性）**：报告命中 AI 味高/中项、或建议返工 → **必须按建议改写后重跑复审，直到不再命中高/中 AI 味、结论为"否"才允许发布**。同一问题两轮改不掉就换模型复核。
**输出控制**：脚本 prompt 已内置"直接给结论、总输出≤500字"；若模型输出思考过程撑爆额度导致报告截断，重跑或换模型即可。

**实测案例（2026-08-23 丁真文案）**：glm-5.3 抓出——"带动近4000万文旅经济"是通稿腔（建议改"赚了近4000万"类口语）；"当初的运气，就是清醒"与"哦豁…巴适得很"两句金句堆叠在结尾前可删一句；"那么问题来了"是互联网老梗（套路过渡）；方言"黢黑（北方）"+ "巴适（四川）"混用略不一致。这些就是复审要抓的典型。

### Step 5 发布到今日头条微头条（浏览器辅助 · 已验证流程）

**头条无公开内容发布 API，不能 curl/脚本自动发。** 唯一自动路径是 browser 走 user profile（登录态在用户浏览器里）。2026-08-23 已实测跑通（丁真文 531 字发布成功，进"审核中"）。完整操作序列：

1. **检查浏览器**：`browser action="status"`（确认 running/CDP ready）；`browser action="tabs"` 看现有标签
2. **确认登录态**：打开 `https://mp.toutiao.com/profile_v4/weitoutiao/publish`，`action="snapshot"`：
   - ✅ 登录成功标志：能看到"发布 / 微头条"、账号名（如"棱镜折射的个人主页"）、正文编辑器
   - ❌ 未登录标志：页面是登录页（"验证码登录 / 扫码登录"按钮）→ 走下面的 Cookie 注入
3. **Cookie 注入（用户提供 sessionid 时）**：在 toutiao.com 域下执行 evaluate：
   ```js
   () => {
     const sid = '<用户给的sessionid>';
     document.cookie = 'sessionid=' + sid + '; path=/; domain=.toutiao.com';
     document.cookie = 'sessionid_ss=' + sid + '; path=/; domain=.toutiao.com';
     return document.cookie;
   }
   ```
   然后 `action="navigate"` 到发布页，再 snapshot 验证登录。注意：**先注入再导航**，注入发生在 toutiao.com 域下才生效；sessionid 通常同时给 sessionid_ss，两个都要写。注入后若仍登录失败 → 走 Step 6 邮件通知。
4. **填正文**：snapshot 找到正文编辑器（contenteditable），用 evaluate 注入：
   ```js
   () => {
     const text = `正文...`;
     const el = document.querySelectorAll('[contenteditable="true"]')[0];
     el.focus();
     el.innerText = text;
     el.dispatchEvent(new InputEvent('input', {bubbles:true, inputType:'insertText', data:text}));
     return {ok:true, len:text.length};
   }
   ```
   注入后**必须再 snapshot 验证**：`正文字数：XXX` 已更新、段落结构完整（框架可能不响应 innerText，需要重试，改用 execCommand('insertText') 或逐段 paste）
5. **发布前最终查重（硬性 · 2026-08-24 用户铁律；发布后删是事故不是流程）**：点发布前**必须**再扫一遍作品管理页列表（已发布+审核中，近 7 天为主，重点看今天）+ 台账，确认没有同主题/同事件/同角度的已发布或审核中文。**校验必须前置到发布动作之前**——发布后再发现撞车属于流程事故，要按事故处理（删文 + 邮件 + 复盘根因）。发现撞车 → 停止发布，换选题或征求用户意见（可给出"删旧发新 / 换题 / 不发了"选项）。
6. **发布前用户确认（硬性 · 2026-08-25 强化）**：发布是公开外部操作，把文案+发布动作发给用户确认，**确认消息必须包含 Step 2 的查重清单**（"台账已查 N 条 / 作品管理页已查 M 条，无同主题/同事件/同角度"）；查重清单缺失 = 流程未走完，**禁止点发布**。用户说"发布"才点
6. **点发布**：snapshot 拿到"发布"按钮 ref → `action="act" kind="click"`。成功后 URL 跳转到作品管理列表页，snapshot 确认第一条显示新文+状态"审核中"
7. **发布后检查**：作品列表第一条 = 刚发的文，时间戳是当前时间，状态"审核中"→ 成功；若状态"审核未通过"或文没出现 → 视为失败，走 Step 6 邮件通知

发布形态：正文 400-500 字即可，可附 1 张新闻配图（选图规则参考 news-social-writing：必须 qwen-vl-max 验图，无文字水印，不误导）。

### Step 6 发布后记录台账（硬性 · 2026-08-24 新增）

**每次发布成功后（或异常未发）都要追加一行到 `logs/published.log`**，供下一次查重用：
```
YYYY-MM-DD HH:MM | 主题关键词 | 发布状态 | 首句摘要
```
写入要点：主题关键词要能覆盖同主题变体（如"甲醛白菜""敌敌畏消杀"），方便 grep 查重；发布失败/异常也记（标注状态），避免下次又选同题。

### Step 7 异常邮件通知（硬性 · 用户 2026-08-23 要求）

**触发条件（任一即发邮件到 18518007500@163.com）：**
1. **Cookie 过期/登录态失效**：导航到发布页后 snapshot 是登录页、或注入 Cookie 后仍登录失败、或发布页提示重新登录
2. **发布失败**：点发布后作品列表第一条不是刚发的文、状态是"审核未通过"、或报错弹窗
3. **任何导致"该发的微头条没发出去"的异常**

**发送方式**：`scripts/notify_email.py`（smtplib 直连 163 SMTP，SSL 465）。配置在 `config/smtp.json`（user=18518007500@163.com，auth_code 已配置 2026-08-23，to=18518007500@163.com），也可用环境变量 SMTP_USER/SMTP_AUTH_CODE/NOTIFY_TO。

**若 SMTP 未配置**：先写出异常日志到 `logs/publish_errors.log`，并在微信对话里提醒用户"头条发布异常+需要配置邮箱"；配置好后（用户提供 163 授权码）补发。

**163 授权码获取**（用户侧）：163 邮箱网页版 → 设置 → POP3/SMTP/IMAP → 开启 SMTP 服务 → 按提示用手机发短信验证 → 生成授权码（16 位字母）→ 填进 smtp.json 或环境变量。

## 与现有 skill 的关系
- 本 skill 是独立微头条流水线（从热搜到发布全链路），**不是** news-social-writing 的微头条附属产物
- news-social-writing 管公众号正文+微头条（约800字）；本 skill 管纯微头条快手内容（400-500字、方言感、反讽，更"短平快"）
- 发布链路复用 browser profile="user" 经验；写作风格遵循 SOUL.md（反 AI 味）
- 复审脚本思路沿用 news-social-writing 的 ai_taste_check.py，但微头条无标题、更口语化，提示词单独适配

## 深度单篇产线（2026-08-29 新增 · 用户批准）

**触发场景**：想把一个话题写深、写透（如"湖北可乐为什么是600ml"这种有历史纵深、有商业博弈、有地域文化的话题），产出 1500-2500 字的长文微头条。区别于快讯流 400-500 字短篇，深度单篇拼的是**故事+知识+情绪**三重密度。

**写作方法论（用户 2026-08-29 硬性要求）**：**写之前先选题 → 设计结构 → 再逐部分写**。不允许拿到题就从头往下遛——深度单篇的结构是文案的第一生产力，必须先定骨架再填肉。

### 第一步：选题（比快讯流更挑）
深度单篇的题必须同时满足：
1. **有历史纵深**：能往回挖几十年（湖北可乐→90年代两乐商战；而不是"今天某地涨价了"）
2. **有地域/圈层限定性**：自带"只有XX知道"的稀缺感（如湖北600ml、天津山海关汽水、东北冻梨）
3. **有商业/社会机制的里子**：背后能讲出经济学、博弈论、政策演变（运输成本、规模效应、合资改制）
4. **有情绪钩子**：反差（全国都500ml凭啥湖北600ml）、惊讶（"啊？难道你们不这样吗"）、羡慕/酸（多喝100ml）
5. **查重照旧**：同主题/同事件/同角度一律不选，过台账+作品管理页双渠道
加分：有具体年份、有具体厂名/人名、有价格数字（2.9元 vs 3块多）、有可搜到的图片素材（视觉中国/小红书截屏）

### 第二步：设计结构（写前必做，呈现给读者前先定稿）
参考已验证爆款《湖北可乐600ml》的三层递进骨架：

**标题**：反常识质疑句，不用陈述句。"为啥全国只有湖北的可乐是600ml？" > "湖北可乐600ml的原因"。质疑句把读者变成同谋。

**开头五连击（前200字完成）**：
1. 热点背书（"又双叒叕上热搜了"）——证明值得看
2. 事实反差（600ml vs 500ml + **价格几乎持平**）——反差是钩子的核，必须带上价格/数字
3. 全网情绪替读者说出（"酸成柠檬精""薅羊毛"）
4. **本地人视角反杀**（"啊？难道你们喝的不是600ml吗？"）——制造信息差喜剧，这手最出效果
5. 画面感比喻收口（"别人吃小杯冰淇淋，你们端着大桶炫"）

**正文三段：故事 → 道理 → 情感**（顺序不能乱，情绪逐级抬升）：
- 01 故事段：讲人的博弈（两乐商战、加量不加价、消费者用脚投票）。要有具体年份（1986/1994）、具体厂名（八王寺/山海关/汉口二厂）、具体动作（"比500毫升多100毫升"标语）。像纪录片，不是说明书
- 02 道理段：讲机制（本地建厂省运费、规模效应摊成本）。用大白话讲透，零术语腔（"运费都够多灌100ml可乐了"）
- 03 情感段：落回生活（煮姜丝可乐、大人小孩冲突）。让读者代入一日三餐的烟火气

**结尾两步**：1）符号化——把小事拔高成意象（"多出来的100ml，像一道被时间封存的暗号"），赢家重新定义（"赢家不是两乐，是湖北消费者"）；2）行动号召——"下次去湖北，买一瓶喝那多出来的100ml"。结尾不总结、不升华腔，给可传播的情感符号。

### 第三步：逐部分写（填充顺序：先开头，再01→02→03，最后结尾）
- **金句密度**：每 400-500 字至少一个记忆点（比喻/对仗/文化梗），如"朝三暮四的把戏，庄周时代就玩剩下的""出了襄阳城就失效的独家秘笈""两乐拿它当子弹，湖北人拿它当福利"。金句是转发动机
- **证据链**：每一段观点都要挂具体数字/年份/厂名，拒绝"很久以前""贵不少"；价格、容量、日期是硬通货
- **视角切换**：像剪辑一样换机位——全国网友（酸）→ 湖北人（懵）→ 商家（博弈）→ 家庭（生活）→ 作者（升华），但一条线穿到底
- **方言/地域梗克制用**：点缀（"买百事撒""九头鸟""湖北小伢"），不喧宾夺主
- **不用 AI 惯用语**：同快讯流铁律（近日/随着/值得注意的是/这一事件/背后折射出），长文更容易犯通稿腔——每写一段自查一遍
- **文化常识要核实**：引典故（庄周朝三暮四、可乐发明史1886年）必须确认准确，错了整段垮掉
